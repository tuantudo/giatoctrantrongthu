## PILLAR 2: ĐỐI SOÁT CLOUDFLARE WAF (CLOUDFLARE WAF RECONCILIATION)

| Endpoint kiểm thử | Phương thức | Kết quả Probe thực tế | Trạng thái WAF | Đánh giá Kỹ thuật |
| :--- | :---: | :---: | :---: | :--- |
| `/api/member/login` | POST | **`HTTP 400 Bad Request`** | **`VERIFIED ALLOWED`** | Vượt qua WAF, tới máy chủ Express NAS xử lý. |
| `/api/member/proposals` | POST | **`HTTP 401 Unauthorized`** | **`VERIFIED ALLOWED`** | Vượt qua WAF, tới máy chủ Express NAS xử lý. |
| `/api/member/change-password` | POST | **`HTTP 302 Found`** | **`VERIFIED ALLOWED`** | Vượt qua WAF! Đã được Tuấn miễn trừ thành công. (Trả 302 do NAS đang chạy code V2.0.0). |
| `/api/member/support` | POST | **`HTTP 403 Forbidden`** | **`BLOCKED BY WAF`** | Bị quy tắc *Emergency Block API Mutations* chặn do endpoint mới chưa nằm trong danh sách miễn trừ. |

### Khuyến nghị cấu hình Cloudflare WAF:
Quy tắc hiện tại:
```text

```
Cần được Tuấn cập nhật bổ sung thêm endpoint hỗ trợ thành viên trước khi đưa vào sử dụng chính thức:

## PILLAR 3: TƯƠNG THÍCH CƠ SỞ DỮ LIỆU (DATABASE COMPATIBILITY: SQLITE & MARIADB 10.11)

Toàn bộ mã nguồn mới được thẩm định tính tương thích chéo giữa SQLite cục bộ và MariaDB 10.11 trên Production NAS:

1. **Giao dịch Nguyên tử (Transactions):**
   - Sử dụng wrapper `withTransaction(async (db) => { ... })` từ `server/governance.js`.
   - Đối với MariaDB: Tự động khởi tạo kết nối pool, thực thi `START TRANSACTION`, `COMMIT` và `ROLLBACK` khi có lỗi.
   - Đối với SQLite: Thực thi `BEGIN TRANSACTION`, `COMMIT` và `ROLLBACK`.
   - Kết quả: Đã kiểm chứng qua Test 7 của bộ kiểm thử bảo mật đổi mật khẩu $\rightarrow$ `VERIFIED`.

2. **Cập nhật Mật khẩu (Password Hash Updates):**
   - Câu lệnh SQL chuẩn: `UPDATE accounts SET password_hash = ? WHERE id = ?` và `UPDATE admin_users SET password_hash = ? WHERE username = ?`.
   - Không phụ thuộc phương ngữ (dialect-independent), hoạt động đồng nhất trên cả 2 hệ quản trị CSDL $\rightarrow$ `VERIFIED`.

3. **Sinh Khóa Chính (ID Generation):**
   - Toàn bộ các bảng mới tạo bản ghi (`audit_logs`, `proposals`) sử dụng `crypto.randomUUID()` sinh khóa UUID v4 chuẩn ở tầng ứng dụng Node.js, không phụ thuộc vào `AUTO_INCREMENT` hay `ROWID` $\rightarrow$ `VERIFIED`.

4. **Lược đồ Nhật ký Kiểm toán (Audit Log Schema):**
   - Các trường ghi nhận: `id`, `timestamp`, `actor_id`, `actor_role`, `action`, `target_type`, `target_id`, `details_json`, `ip_address`, `user_agent`, `created_at`.
